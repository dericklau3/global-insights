# 新闻研究、事实核验与 GitHub 归档

## 新闻研究与内部资料表

1. 获取源材料，提取：事件主体、日期、地点、产品/模型名称、关键数字、价格、服务对象、推出/上市状态。
2. 打开官方首发材料，核实用户截图或 X 帖子里的说法。只凭单条热帖不推断官方产品功能。
3. 寻找必要的第二来源来补充背景或辨认争议；冲突时保留不同口径，并优先引用可追溯的原始文件。
4. 收集素材时记录真实 URL、截图来源、拍摄场合和使用许可条件。
5. 把“用户可以用”与“公司展示的实验案例”、“现已上线”与“即将推出”、“官方测试”与“独立复测”严格区分。
6. 价格要写清货币、地域、订阅/API 类型、生效期及是否需其他付费设备。

内置的 [研究笔记模板](../assets/research-notes-template.md) 只供内部核查，**不是可发布文章的一部分**；如要长期留痕，可在仓库另存非文章研究记录，但用户只要求正文时无需额外提交。

## 针对不同输入的具体处理

- **X post**：核对 X 原文、发布时间和作者身份；研究涉及的产品/公司的原始文件，不盲目复述观点。
- **官方产品发布**：核查地区、价格、规格、功能需不需要账号/订阅/外设，注意“演示”与“普遍可用”。
- **GitHub 开源项目**：优先从 README、代码入口、关键模块、Issue/Release 等验证真实功能；不要把 roadmap 写成已经实现。
- **财经/商业事件**：分清财报数字与媒体评论，标注口径和期限，不编造交易建议、市场数据、竞争结论。
- **批量新闻表**：若要选题，按关注度、潜在读者、真实性和素材可得性排序；正式写作前逐条复核。

## 归档布局

默认目标仓库：`https://github.com/dericklau3/global-insights`。

- 先检查当前 GitHub 结构、默认分支及最新内容；用户已经选定文件路径就原地更新。
- 日期文件夹默认用北京时间 `MM-DD`：`10-14/`。
- 文件名按同一日期 `01_...md`、`02_...md` 依次编号；避免有歧义的重名文件。
- 正文图片与独立封面放在同级 `assets/`；正文相对路径 `assets/...`。
- `README.md` 可作为日期目录的文章索引及封面链接入口，但正文里不展示封面。
- 每轮修改可提交可追溯的 Git commit；修改标题时同步索引。
- GitHub 私有仓库必须有授权连接才能写入。不要写“已同步”除非能核实 commit 和文件内容。
- 如果没有 GitHub 权限，生成可下载的文件/目录包，交代尚未提交。

## 修改时的防误操作规则

- 只改要求涉及的文章和索引；不清理其他日期的资产。
- “去掉封面”优先理解为 **去掉文章正文的封面引用**，并且保留独立封面文件，除非用户明确让删除封面文件。
- “删除 10 月 14 日日期框”要同时检查当天的多篇文章，正文自然提到新闻发生日期不必删除。
- “结尾去掉资料来源”要删去尾部整个链接块、编辑说明和多余分隔线，不可误删文章的自然收尾。
- 之前用户明确规定的格式持续应用到后续文章，除非用户修改偏好。

## 交付与验收

- 内容完整性：稿件与新标题对应、有深度且无虚构。
- 文件完整性：序号、日期目录、图片引用、封面路径准确。
- 视觉完整性：封面 2.35:1 无字，正文图有内容价值且与事实相符。
- GitHub 完整性：文件可读取、对应图片存在、最新 commit 能查询。

若用户仅要求写稿，不在缺乏明确授权的情况下发布到真实公众号后台或创建新的公开仓库。
